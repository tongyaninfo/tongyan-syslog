# 版本与发布

本目录记录产品版本规则、发布约定与数据库升级约定。当前源码为 **0.1.0，未封版，无发布**；尚无任何环境部署或升级记录。

## 版本规则

- 根 [VERSION](../../VERSION) 是产品版本的唯一权威来源，采用 `MAJOR.MINOR.PATCH`。
- 破坏既有公开合同或升级兼容性升主版本，兼容新增功能升次版本，兼容修复升修订版本；预发布使用 `-rc.N` 后缀。
- 前端 `package.json`、后端程序集版本、界面展示版本从根版本或其投影读取，不各自维护一套编号。
- 数据库迁移编号表示结构与升级链，不跟随产品版本机械递增；每次封版记录当时的目标迁移与结构快照摘要。
- 产品版本不能代替数据库事实。同一产品版本在未封版开发期间可能出现多个结构版本；旧库必须按自身迁移历史识别，不根据程序版本猜测。
- 发布清单（如后续引入）必须随制品嵌入，声明产品版本、目标数据库版本、支持的升级来源与迁移摘要；外部同名文件不能替换已构建制品的清单。

## 封版流程

1. 确认目标版本、范围、兼容性与数据库影响；无数据库变化时明确写「无」。
2. 更新 [VERSION](../../VERSION)、前端版本投影、[CHANGELOG](../../CHANGELOG.md)、`docs/releases/<版本>.md` 与发布清单（如已建立）。
3. 记录完整迁移链、脚本摘要、支持的起始结构、运行兼容范围、数据转换与恢复步骤。
4. 运行文档检查及对应构建/测试；未运行的检查不报告为通过。
5. 制品使用不可变标识；已交付版本不覆盖、不改写历史台账。

## 数据库升级约定

- 实际结构以数据库迁移历史为准；未知迁移、来自更高版本的库或非连续历史必须停止并报告，不自动降级或重建空库。
- 普通启动不自动建库或迁移。完整升级工具的目标是在停写状态通过显式维护入口完成一致性备份、迁移与校验，并且不建立管理或接收监听；当前仅有控制库首次初始化和管理员引导，通用升级/备份/恢复链尚未实现。
- 当前单 Api 宿主组合 Ingest：管理服务写 SQLite，日志适配器写 ClickHouse。升级前必须停止应用写入并核对数据库在途请求；两类存储分别协调结构变更，不存在跨 SQLite 与 ClickHouse 的统一事务，也不允许运行实例竞相迁移。
- 升级失败保留数据库、备份和状态，不覆盖或删除；普通重启不重复升级。
- 优先向后兼容的增量变化；字段收紧、重命名、删除与数据回填必须说明旧数据处理、失败恢复与影响范围。
- 历史迁移与已封版台账不得重写，修正通过后续增量版本完成。

## 发布记录模板

封版或实际发布时新增 `docs/releases/<版本或日期>.md`，至少包含：版本与日期、构建标识和制品摘要、范围摘要、兼容性、数据库影响、完整迁移及摘要、验证结果、升级与回滚步骤、未验证边界、实际执行授权与目标环境。
