## 阅读顺序

1. 产品规划：先确认目标用户、一期闭环与明确排除项，避免把扩展方向写成一期承诺。
2. 功能需求清单：按「接入 → 解析 → 检索 → 留存 → 告警 → 管理」拆分编号，每条给出可执行验收点。
3. 一期实施方案：落实进程边界、存储选型、接收协议细节、解析器格式与告警模型，并登记待定项。

已接受单 .NET 宿主、单节点 ClickHouse 日志存储与内嵌 SQLite 管理库，替代初始化时的全 SQLite/双宿主草案。参见 [ADR-0001](../adr/ADR-0001-轻量化长周期日志架构.md)。接收默认关闭，普通启动不建库；真实 ClickHouse、端口、设备、浏览器与性能验收尚未进行。

## 内容要求

- 区分「规划」「已实现」「已验证」「已部署」；方案完成不等于功能实现。
- 涉及存储、迁移、端口与通知渠道的决定，必须在 [ADR](../adr/README.md) 中留档，不在方案里口头定案。
- 架构待定项见[项目目录规划](../项目目录规划.md#架构待定项)，方案确认后同步更新该节。
- 不写真实日志样本、主机名、账号、密钥或个人绝对路径；示例使用合成报文与文档保留网段。

入口与导航见[文档中心](../README.md)。
