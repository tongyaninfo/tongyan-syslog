# 首批后端运行与验证

更新：2026-11-10。架构已采纳；本页对应首批源码，不能视为一期全部能力或生产可用性验收。完整范围仍以[一期实施方案](一期实施方案.md)为准。

## 已落地的链路

未登记来源在许可网段内进入独立的[内存样本暂存](未登记设备暂存.md)，每 IP 最多 100 条、重启清空。以下流水线表示已登记启用来源的正式入库；停用来源和来源快照故障继续拒绝接收。

```text
设备 → UDP / TCP / TLS / RELP → 来源白名单与限速 → 有界内存队列
     → RFC 5424 / 3164 解析 → 本地有界暂存 → 批量 HTTP → ClickHouse

Web 管理台 → 同源 HTTPS API → 会话与管理员权限 → 来源范围
           → ClickHouse 检索 / 原始字节详情
           → SQLite 来源、保留/监听配置、账号、会话、号段和事务审计
```

一个 `Syslog.Api` 进程承载管理 API 和 `Syslog.Ingest` 后台任务。解析器在独立 Engine 类库；不读取网络、文件或数据库。首批 API 见[接口合同](../api/README.md)。当前已有登录、总览、日志检索/详情、来源与保留管理台源码，尚未生产部署；前端接入不改变本页后端能力和验证限制。

## 构建与本地自动验证

SDK 由根 `global.json` 固定为 .NET 10.0.300，并允许同系列补丁。依赖版本集中在 `backend/Directory.Packages.props`，各工程生成 `packages.lock.json`。

在仓库根执行：

```sh
dotnet restore backend/Syslog.slnx --locked-mode
dotnet build backend/Syslog.slnx --no-restore
dotnet test backend/Syslog.slnx --no-build
node scripts/check-docs.mjs
```

自动测试使用合成协议报文、内存 SQLite、模拟 ClickHouse HTTP、进程内 TestServer 和测试输出目录中的暂存文件。不会创建 ClickHouse 真库、绑定操作系统端口或读取真实证书。暂存测试产物保留在 `bin/.../TestResults/`，不自动删除；没有执行确认后的暂存文件回收测试。内存 SQLite 验证不等价于真实磁盘 WAL 崩溃恢复验证。

前端安装、`setup/lint/test/build`、`build:backend` 及 `preview:synthetic` 的实际用法见[前端说明](../../frontend/README.md)。合成预览默认绑定 `127.0.0.1:8019`，读取前端构建并提供明确标识的内存合成数据，不连接真实后端存储或设备。生产仍要求同源 HTTPS 与 Secure Cookie。接收配置功能另增显式版本 2 控制库迁移；构建与浏览器预览不等于真实设备、ClickHouse 或生产验收。

## 运行前的配置

### 本地真实管理台测试

已具备受信任的 localhost 开发证书时，可以在获准的本地环境使用真实 .NET 后端验证初始化与用户管理，不需要先启用 ClickHouse 或设备接收。先构建前端并用 `frontend/scripts/copy-to-backend.mjs` 复制到后端 `wwwroot`，再构建后端。选择独立持久化目录作为内容根，将公开的 `appsettings.json` 复制进去；不要把既有私有配置或正式控制库用于首次配置测试。

启动时显式传入内容根、静态目录、绝对 SQLite 路径和 HTTPS 地址。纯管理台验证可设置 `Ingest:ForceDisabled=true`，此时启动和运行期开关都禁止设备接收。设备接收验证需对应环境授权。一般 `Ingest:Enabled=false` 只作为部署基线，已保存监听配置会在启动时覆盖它。本地允许的 Host 为 `localhost;127.0.0.1`，证书名称为 localhost 时使用 `https://localhost:<port>` 访问。经局域网 IP 访问 HTTPS 需要匹配该地址的证书和主机配置。

普通启动、访问页面及初始化状态查询均不创建管理员；用户提交首次配置才写入真实 SQLite。主测试实例应保留为空，让用户自行创建账号。自动化账号/权限验证使用另一独立目录，不能占用或重置用户首次初始化机会。运行目录保留供后续测试，不自动删除。

登录后总览使用管理员会话鉴权的 SignalR，每秒共享采样，无订阅者不读库；接收关闭且无来源时显示真实零计数与关闭状态。`/health/live` 只证明进程存活。未配置 ClickHouse 时日志查询仍不可用，不能把账号功能可用描述为真实日志链路已验收。消息和持续鉴权边界见[接口合同](../api/README.md#实时看板-signalr-合同)。

### 配置项

部署基线默认接收 `Ingest.Enabled=false` 且监听器列表为空。「接收配置」提供默认关闭的 UDP 514、TCP 514、TLS 6514、RELP 2514，绑定 `127.0.0.1`；保存后在下一次启动应用。默认管理地址为 `https://127.0.0.1:7443`，需要提供受控的 HTTPS 证书配置；没有自动生成证书或开放防火墙。

应用依次读取标准配置、可选 `appsettings.Local.json`、环境变量和命令行覆盖。私有配置文件不进入仓库。`ClickHouse.Password`、TLS PKCS#12 密码、证书路径及数据库连接参数必须在目标环境提供，不用命令行传递密码。`appsettings.Local.json` 默认相对于宿主内容根目录；以实际启动方式确认该目录。

上述配置完成后，宿主在接收工作器启动前读取 SQLite 中已保存的监听快照，只覆盖接收开关及监听字段，`Ingest:ForceDisabled` 仍优先。完整顺序、证书引用、升级与 ACK 合同见[接收配置与 RELP](接收配置与RELP.md)。

| 配置 | 当前默认与语义 |
| --- | --- |
| `ControlStore.ConnectionString` | `Data Source=syslog-control.sqlite;Mode=ReadWrite`；相对进程工作目录，生产应改为明确的数据卷路径 |
| `ControlStore.IdBlockSize` | 4096；持久预留后发号，允许空洞；恢复旧控制库备份前必须核对 ClickHouse 已用 ID 高水位 |
| `ClickHouse.Endpoint` | `http://127.0.0.1:8123/`；目标跨主机时配置受信 HTTPS 与网络访问限制 |
| `ClickHouse.Database` | `syslog`；自动初始化将仓库 SQL 绑定到配置指定的数据库 |
| `ClickHouse.Username/Password` | 配置账号；需要日志表的读取和写入权限。缺失对象的初始化需要相应的 CREATE 权限，清空日志需要该表的 TRUNCATE 权限 |
| `Ingest.QueueCapacity/QueueBytes` | 4096 条 / 64 MiB；每条另计 512 字节元数据预算，实际总进程内存还包含连接、字符串、批次和运行时 |
| `Ingest.SpoolBytes` | 1 GiB；暂存满后停止消费内存队列，继续接收可能丢弃，绝非无限缓存 |
| `Ingest.BatchEvents/BatchRawBytes` | 256 条 / 512 KiB 原文字节，较早到达上限即提交；JSON 与 base64 包络会更大 |
| `Ingest.BatchFlushMilliseconds` | 500 ms；低流量批次等待时间 |
| `Ingest.MaxMessageBytes` | 65536；UDP 受协议自身负载上限约束，超限、截断均计入丢弃 |
| `Ingest.MaxConnections/MaxConnectionsPerAddress` | 2000 / 4；TLS 另有限制同时握手数 64；已登记来源每秒最多 10 次新连接 |
| `Ingest.MessagesPerSecondPerSource` | 每来源 5000 条/秒，超限丢弃，不表示已验证此吞吐 |
| `Ingest.SourceRefreshSeconds` | 10 秒；来源修改存在刷新延迟，失败时拒收并关闭连接 |
| `Ingest.ForceDisabled` | 默认 false；为 true 时优先关闭接收，不改写已保存配置 |
| `Ingest.TlsCertificates` | 服务器证书引用字典，每项含 CertificatePath/CertificatePassword；网页只选择标识 |

部署监听器对象含 `Enabled / Address / Port / Transport / Framing / FrameTimeoutSeconds / IdleTimeoutSeconds / CertificateId`，兼容原有直接 CertificatePath/CertificatePassword 配置；网页合同只提供 CertificateId。`Transport` 为 `udp/tcp/tls/relp`，TCP/TLS 的 `Framing` 为 `octet-counting/newline`（LF/CRLF）；TLS 仅启用 1.2/1.3，无明文回退。TCP/TLS 队列满时当前帧计入丢弃并断开；RELP 在暂存成功后确认，失败不回成功 ACK。来源按传输对端 IP 精确匹配；报文内 hostname 不是认证身份，NAT 后多设备共用地址的精细识别尚未实现。

## 显式初始化入口

以下是供指定环境获准后使用的命令。各环境实际执行情况以对应变更记录为准；未初始化真实 ClickHouse。

控制库和首个管理员也可以通过首次配置页显式初始化，依据 [ADR-0002](../adr/ADR-0002-管理员配置与显式网页初始化.md)。配置 HTTPS 与明确数据位置后，服务器本机访问管理台，未配置账号时自动进入初始化页。填写并提交才写入控制库，访问页面和状态探测不会自动建库。请求要求本机连接和 localhost/回环 Host，拒绝转发头，不能通过反向代理对外开放首次提交。远程安装可使用受控隧道。

已有完整空账号库可复用，结构不完整或版本未知的库不会自动修复。若全新库初始化中断留下不完整文件，页面会提示服务错误，需要维护者核查后处理，后续请求不会覆盖该文件。任意账号已存在时不再允许匿名初始化，即使账号全部停用也不会重新开放注册。以下 CLI 入口仍保留。

1. 审阅 [SQLite 初始化 SQL](../../backend/src/Syslog.Api/Data/001_control.sql) 和 [监听配置版本 2 SQL](../../backend/src/Syslog.Api/Data/002_listener_settings.sql)，配置隔离数据目录和连接字符串后，显式调用：

   ```sh
   dotnet run --project backend/src/Syslog.Api -- --initialize-control
   dotnet run --project backend/src/Syslog.Api -- --bootstrap-admin
   ```

   管理员从终端读取账号和密码，密码不回显。没有内置账号密码；已有管理员时拒绝再次 bootstrap。普通启动不创建表或数据库。

   全新初始化依次执行 `001` 至 `003`。既有版本 1 在授权、备份及维护窗口后执行 `dotnet run --project backend/src/Syslog.Api -- --migrate-listeners`。版本 2 保存忽略严重级别前须显式执行 `dotnet run --project backend/src/Syslog.Api -- --migrate-source-filters`。维护命令不会启动监听，目标库由受控配置确定。

2. 启动所配置的 ClickHouse 实例。应用首次访问日志存储时检查目标库和表，缺失时使用 [初始化 SQL](../../backend/src/Syslog.Ingest/Data/events.sql) 创建，并校验日志列。最低目标版本为 26.8，需要支持 `text` 索引。既有表的索引调整与结构迁移仍需维护操作。

3. 配置 HTTPS、允许的 Host、ClickHouse 应用账号，启动 API，登录后登记来源 IP、来源时区和保留天数。确认存储与来源有效，再通过「接收配置」保存所需监听设置并重启，检查每个端点实际状态。绑定、证书部署与放行端口必须取得对应环境的授权。

## 查询和保留的实际边界

- 查询时间按 `received_at`，UTC 毫秒精度；时间窗最多 30 天，但可选择保留期内任意历史 30 天。超出窗口需拆分，当前没有跨年单次检索任务。
- 默认取 100 行，最多 500 行，游标绑定筛选条件与来源范围。不执行精确 `COUNT(*)`；列表不读取原文，详情才读取 `raw_base64`。
- 关键词是区分大小写的 ASCII 全词 AND，索引使用 `splitByNonAlpha`，查询使用 `hasAllTokens`。中文、混合中文及纯符号输入返回 `unsupported_search_token`；没有自动退化为 `LIKE '%…%'`。例如 `link` 不等于 `LINK`，也不是 `uplink` 的子串。
- 日志表按接收月份分区，排序键为 `(received_at, event_id, source_id)`，前两列与列表游标排序一致。`message/raw_base64` 使用 ZSTD(3)。原文按 base64 表达完整字节，不能用显示文本替代证据；额外存储成本待压测量化。
- 前台最多同时 4 个查询，每个默认执行超时 10 秒、2 个 ClickHouse 线程、512 MiB 查询内存、4 GiB 读取上限、16 MiB 响应上限。失败返回真实错误，不能把超时或截断算作查询成功。应用限制不能替代 ClickHouse 服务端账号配额。
- 保留天数支持 1～3650；修改只影响之后接收日志的 `expires_at`。查询排除在查询开始时已经过期的日志，但**当前没有物理清理任务或 DELETE TTL**，所以过期不等于磁盘释放。历史保留调整、删除审计任务、容量治理完成前，不能将此版本作为长期生产留存系统。
- 管理员可在日志检索页确认「清空日志」，清空配置指向的 ClickHouse 日志表。操作覆盖该表的全部记录，包括过期数据。SQLite 管理和审计数据、队列及暂存文件独立保留，后续接收或待写入批次仍可产生新记录。
- 当前只有管理员角色；已实现首次配置、账号管理、登录、会话过期/退出及管理变更可靠审计。细分角色与来源级用户授权尚未实现。账号停用、改名或密码重置使旧会话失效，最后一个启用管理员及当前登录账号不可被停用。

## 故障与暂存语义

暂存不是归档。每批先写带摘要的临时包络并 `Flush(true)`，改名为 `.batch`；发送前写 `.sending` 标记；确定 ClickHouse 成功后写 `.acked` 标记再回收该批暂存。只有启用接收进程才会创建和回收这些运行文件。

| 状态 / 错误码 | 含义与首版行为 |
| --- | --- |
| `running` | 暂存/发送任务运行，不代表每条已入库 |
| `spool_full` | 暂存配额不足，等候释放；内存队列仍有界，溢出计数 |
| `retrying` | ClickHouse 暂时不可用或写入未确认；保留队首批次，退避重试，并报告本次存储错误码 |
| `storage_contract_rejected` | 本地存储合同检查拒绝，尚未发送 HTTP；停止接收继续污染队列，保留暂存用于修复 |
| `spool_recovery_required` | 发现未完成 `.tmp`，拒绝正常启动 |
| `spool_ack_cleanup_required` | 确认后回收中断留下 `.acked`，明确要求恢复；不重发该批 |
| `spool_batch_exceeds_capacity` | 单批超过整个暂存配额，不能靠等待释放解决，明确失败 |
| `source_registry_unavailable` | 无法更新来源快照，拒收、关闭连接并按周期重试刷新 |

重启发现 `.sending` 会自动提交同一批次，事件标识和去重标记保持不变。文件数据刷新不能证明突然掉电时目录项已经持久化；ClickHouse 去重窗口有限，不承诺严格只写一次、UDP 无丢包或断电无丢失。内存中尚未持久化的数据在停止/异常时可能丢失。指标是进程累计值，重启会复位；持久待发送批次数和占用从磁盘重建。尚未采集操作系统接收前丢包、真实磁盘剩余空间或 ClickHouse 内部合并负载。

## 真库验证的下一步

在明确实例、版本、磁盘和资源预算后，执行以下验证；本次均未执行：

1. 初始化 SQL、核对实际字段/排序/索引，写入合成正常与异常报文，查询列表和原文逐字节比对。
2. 对 API 实际 SQL 运行 `EXPLAIN indexes = 1`，核对 text 索引、分区裁剪、排序读取；记录 `read_rows/read_bytes/query_duration_ms/memory_usage`。
3. 以约 1000 EPS、30 天 25.92 亿条的规模，持续写入同时跑跨设备常见关键词、低频/高频/零命中、单设备时间范围、组合字段查询。冷/热缓存分别测，前台并发 1/4，记录首屏前 100 条 P50/P95/P99。
4. 目标仍为核心查询 P95 ≤5 秒；没有达到就调整索引/排序/投影或资源并复测，不用同步超时、转后台或返回不完整数据代替达标。
5. 在获准隔离网络验证 UDP/TCP/TLS/RELP、来源限速、证书错误、连接与队列上限、存储中断、重启及恢复；破坏性/删除恢复演练须先取得具体授权。
