依据是用户提出的“开发用户管理菜单、配置用户，系统初次启动的时候应当进入用户配置页面，初始化管理员用户”，并回复“按此方案实施”。本方案复用现有控制库、认证与六语管理台，授权包括本文前后端实现、隔离测试及合成预览。

## 实施前核实的基础

- [users 表](../../backend/src/Syslog.Api/Data/001_control.sql)已有用户名、规范化用户名、密码哈希、角色、启用状态、会话版本和创建时间。角色约束目前仅允许 `admin`。
- [控制服务](../../backend/src/Syslog.Api/Service/impl/ControlStore.cs)已有一次性管理员创建、密码哈希、安全会话、集中发号、事务审计和本人修改密码逻辑。
- 当前管理员只能通过 `--initialize-control` 和 `--bootstrap-admin` 命令创建。普通启动不建库，前端没有初始化页或用户管理页。
- 当前登录、业务菜单及后端业务权限均以管理员为基础，六语、自动主题和图文帮助已经建立。

## 本次实施范围

### 用户管理

侧栏新增“用户管理”，仅管理员可访问。支持用户名搜索、启用状态筛选、分页、新增、修改用户名、启用、停用及为其他账号重置密码。

本次配置的是管理员账号，所有启用账号拥有现有管理员权限，页面明确展示此权限范围。沿用 `admin` 角色，不添加未获需求确认的只读角色、设备组授权、邮箱或手机号字段。账号停用后保留审计关联，不提供删除入口。

列表显示用户名、角色、状态和创建时间。新建填写用户名、密码及确认密码。新建及改名使用 3～64 位 ASCII 字母、数字、点、横线或下划线，不区分大小写查重。历史 Unicode 用户名保持登录兼容，原名未变时可以保存和启停。密码沿用现有 8～1024 个 UTF-16 代码单元且不能全为空白的策略，不返回或回显密码哈希。

修改用户名、停用和重置密码均使该账号已有会话失效。本人改密继续走现有右上角“修改密码”流程。禁止停用当前登录账号，并在事务内保证至少保留一个启用管理员。重置密码及停用均说明影响并要求页面内确认。

### 首次启动

用户访问系统时先读取初始化状态，再决定进入初始化页、登录页或已登录管理台。

| 状态 | 判断依据 | 页面行为 |
| --- | --- | --- |
| 待初始化 | 配置的数据位置确实不存在控制库，或控制库结构完整、版本受支持且没有任何账号 | 进入 `/user/setup`，填写首个管理员用户名、密码和确认密码 |
| 已初始化 | 受支持的控制库中已存在至少一个账号 | 未登录进入登录页，已登录进入管理台 |
| 服务不可用 | 无法读取、权限错误、结构不完整、版本不支持或数据库损坏 | 显示可重试的服务错误，禁止提交初始化 |

普通启动和状态查询保持只读，不自动创建数据库、默认账号或执行迁移。用户在初始化页明确提交后，才允许在配置的数据位置执行现有版本 1 初始化 SQL，并创建首个管理员与审计记录。已有空账号控制库直接复用。对于已经存在但不符合本项目结构的数据库，不覆盖、不修复、不自动补表。

初始化完成后跳转登录页，使用刚设置的账号登录。再次访问初始化页会回到登录或管理台。即使现有账号全部被停用，也不能重新开放匿名创建管理员。

初始化判断和一次性创建由后端保证，不能只依靠前端隐藏页面。并发提交只允许一个请求成功，失败请求不得覆盖已创建的管理员。初始化中断后，根据真实数据库状态显示可重试或服务错误，不假报成功。

### 初始化入口的访问边界

首个管理员创建属于尚无账号时的特殊入口。正式服务仅允许服务器本机直连提交，远程安装通过受控本机访问或 SSH 隧道完成，避免任何先访问网络端口的人抢先取得管理员权限。初始化页面可以展示状态，但不能把同源校验当作安装者身份认证。

提交需 HTTPS、现有写请求保护头和限速。后端依据连接本身判断来源，不信任客户端自报的转发头。初始化阶段不得通过反向代理向其他人开放该提交入口。此边界只针对首次创建管理员，初始化完成后的正常登录与用户管理可按正式部署网络配置访问。

开发合成预览继续使用已获准的本地监听方式和固定合成凭据，可展示完整引导交互，不承载真实口令或真实控制库初始化。

## 接口草案

所有路径相对于 `/api/admin/v1`，沿用 `ApiResult<T>`、真实 HTTP 状态码、字符串 ID 和 UTC ISO 8601 时间。

| 方法与路径 | 权限与输入 | 结果 |
| --- | --- | --- |
| `GET /setup/status` | 匿名，只读 | `{setupRequired,canInitialize}`，不暴露数据库路径、账号、底层异常 |
| `POST /setup/admin` | 首次本机提交，`username/password` | 创建首个管理员，不签发会话，前端随后进入登录 |
| `GET /users` | 管理员，`search/enabled/page/pageSize` | `{items,total,page,pageSize}`，精确总数仅用于小规模账号表 |
| `POST /users` | 管理员，`username/password` | 新建启用的管理员账号 |
| `PUT /users/{id}` | 管理员，`username/enabled/expectedVersion` | 修改账号，旧版本提交返回冲突 |
| `POST /users/{id}/password` | 管理员，为其他账号提交 `newPassword/expectedVersion` | 重置密码并撤销目标账号会话 |

用户管理 DTO 包含 `id/username/role/enabled/createdAt/version`，不扩充现有会话 DTO 的敏感信息。`version` 复用现有 `session_version`，按十进制字符串传输，用于并发修改检查。用户列表默认每页 20 条，上限 100 条，排序与总数以数据库真实结果为准。

首次初始化、账号创建与修改、密码重置使用不同审计动作。写操作在事务内复核操作者仍有有效管理员会话，账号变更、会话撤销和审计同事务提交。审计失败则整个业务变更失败，密码和会话材料不得进入审计、日志或响应。

预期错误区分参数无效、用户名冲突、账号不存在、初始化已完成、初始化来源受限、最后一个管理员保护、禁止本人停用、会话失效和并发冲突。对应六语提示与 HTTP 400/401/403/404/409/429/503，具体错误码随后端 DTO 实施固化。

## 兼容性与影响范围

- 复用现有 SQLite 表，不增加字段或修改历史 SQL，不涉及 ClickHouse 表结构。新增管理员持久化数据仍由现有集中 ID 服务发号。
- 首次页面提交成为现有 CLI 之外的显式初始化入口。实施时同步更新根与后端运行说明中“初始化只能通过维护命令”的描述，仍保留 CLI 维护能力。
- 修改控制服务、初始化及用户管理 Controller、前端启动路由守卫、用户管理页、六语字典、合成预览与图文帮助。
- 直接刷新初始化页和用户管理页需要同步后端静态页面路由。初始化状态读取失败不得降级为“无账号”。
- 新界面继承自动/浅色/深色主题、品牌页脚和六语交互。图文帮助补首次初始化和用户管理，图片只使用合成账号和脱敏内容。
- 保留现有账号和会话合同。用户名变更等管理操作导致目标会话失效，是本次新增的明确行为。

## 验证与交付

1. 在获准的隔离 SQLite 与进程内 TestServer 验证空库、首次创建、重复及并发初始化、审计回滚、密码哈希与数据库不可用。确认普通启动和状态接口不建库、不补表。
2. 验证账号大小写冲突、输入边界、分页、未登录与越权请求、禁用后旧会话失效、重置后旧密码失效、并发版本冲突和最后一个管理员保护。
3. 验证初始化的本机连接限制、HTTPS、写请求保护、限速，以及已初始化后匿名提交被拒绝。测试不使用真实管理员或真实日志。
4. 运行后端构建与测试、前端 lint、测试和构建。真实浏览器覆盖首次初始化、登录、用户管理主要操作、空态与错误态，检查六语、主题和窄屏。
5. 在现有合成预览增加未初始化场景并更新脱敏帮助图片。交付明确区分源码、隔离测试、合成预览与真实部署。
