# 首批存储实施合同

更新：2026-11-10。用户已确认采用 ClickHouse，并批准首批代码、可审阅初始化 SQL 和本机隔离 SQLite 验证。当前已建立首批后端实现，接收默认关闭；未执行真实 ClickHouse 初始化、真实端口监听、设备接入、发布或查询性能验收。

## ClickHouse 对象与访问

[events.sql](../../backend/src/Syslog.Ingest/Data/events.sql)的最低目标为 ClickHouse 26.8。客户端首次访问时以配置的数据库名检查和创建缺失对象，并校验日志列。既有表的兼容性问题通过明确错误报告，结构迁移仍为显式维护操作。

events 保存事件/批次/来源身份、接收/事件/到期时间、传输与来源地址、主机/应用/级别、规范化正文、原始证据和解析状态。event_id 为正 Int64，在 HTTP JSON 中输出十进制字符串；时间为 UTC DateTime64(3)。原始字节显式编码为 raw_base64，避免非法 UTF-8 被改写；message 与 raw_base64 使用 ZSTD(3)，压缩收益未测。

非复制 MergeTree 按接收年月分区，排序为 (received_at, event_id, source_id)，前两列与列表时间/事件 ID 排序一致，正文使用 text 索引 splitByNonAlpha。查询使用类型参数，服务端来源范围为空时拒绝存储查询；单请求最多 30 天、500 条，设置超时/内存/读取与响应字节预算。

首版关键词为**区分大小写的 ASCII 全词 AND**，中文、混合非 ASCII、纯符号返回 unsupported_search_token，不静默退化全库匹配。不提供任意子串/正则、历史任务或准确总数。列表采用稳定游标，绑定过滤条件与授权范围，不冒充事务快照；列表不读取原文字节，详情需事件 ID 与接收时间并再次检查来源/到期。

HTTP 使用 wait_end_of_query=1 并核验错误头和完整正文，禁用重定向；错误脱敏。查询和元数据检查通过 HTTP URL 参数设置只读、预算和输出格式；SQL 和查询绑定值保留在 multipart 请求体。日志查询使用 ISO 8601 时间与字符串形式的 64 位事件标识。重试保持相同 BatchId、事件 ID、内容及插入去重标记。存储暂时不可用或 HTTP 提交未确认时，保留当前批次并退避重试；重启发现 sending 批次也走同一路径。确认写入成功后才推进队列。非复制去重窗口的块数有限，不能承诺任意情况下严格只写一次。客户端发送前合同检查失败显示 storage_contract_rejected，保留批次等待修复。

不设置自动删除 TTL 或定时物理清理，API 仍按事件 expires_at 过滤到期数据。管理员确认「清空日志」后可清空整个 ClickHouse 日志表，包含已到期数据。操作意图与结果写入 SQLite 审计。接收队列和暂存批次独立保留。

## SQLite 控制对象

[001_control.sql](../../backend/src/Syslog.Api/Data/001_control.sql)定义 schema_versions、id_allocations、users、sessions、sources、retention_policies、audit_entries 及相关索引。普通连接使用 ReadWrite；显式初始化才允许创建数据库并设置 WAL。

后续经用户确认的 [002_listener_settings.sql](../../backend/src/Syslog.Api/Data/002_listener_settings.sql) 新增监听配置单例表。配置版本、JSON、操作者和更新时间与 `listener.configure` 审计同事务提交；新初始化顺序执行 `001`、`002`，既有版本 1 通过显式迁移升级，普通启动不迁移。此补充不重写版本 1 账号方案或历史 SQL，详见[接收配置与 RELP](接收配置与RELP.md)。

当前仅 admin 角色。管理员引导、用户管理、来源变更、会话操作使用可靠审计；管理变更与审计同事务。Web 账号管理复用现有 users/sessions/audit_entries，不修改表结构；设备组权限模型尚未实现。来源保留天数支持 1～3650 天，作用于新接收事件，不追溯改变历史 expires_at。

业务 ID 统一通过 IIdService，由控制库事务持久预留号段后在内存分配；默认号段 4096。重启允许跳号，不重复使用已预留号段；不依赖远程发号服务。独立控制库之间当前无全局命名空间保证，不得直接把多个独立实例日志汇入同一事件表。

## 文件暂存与接收边界

同一宿主内，来源匹配与有界队列、解析、号段发号、文件暂存、ClickHouse 批量写入分别计量。暂存使用长度/校验和、临时文件、刷盘、改名与 sending/acked 标记；不声称文件系统目录项掉电持久性已解决。

RELP 已登记来源在文件暂存追加成功后收到 ACK，不能解释为 ClickHouse 入库成功；未登记来源的 ACK 仅表示进入可淘汰、重启清空的内存样本缓存。断线或 ACK 丢失可能导致重传重复，不新增 exactly-once 保证。

发现损坏/未完成暂存或未知发送状态时进入恢复状态，不盲目重发。启动发现 acked 回收残留明确失败为 spool_ack_cleanup_required，不跳过残留后宣称健康。队列与暂存磁盘均有上限，UDP 可丢弃并计数；已接收不等于已持久，更不等于已入库。回收仅允许确认入库的批次，实际文件删除路径本轮未执行测试。

## 初始化、测试与未交付能力

普通 Web 启动和初始化状态查询不创建 SQLite 表或管理员。控制库可通过维护命令或本机 HTTPS 首次配置页的显式提交完成初始化；具体边界见 [ADR-0002](../adr/ADR-0002-管理员配置与显式网页初始化.md)。ClickHouse 缺失库表由首次访问检查并初始化，见[ADR-0001](../adr/ADR-0001-轻量化长周期日志架构.md)的授权补充。

本轮验证采用合成报文、HTTP/流/暂存替身以及已获准本机隔离 SQLite。测试通过只证明覆盖的合同，不证明真实 ClickHouse SQL/索引、TLS 信任链、UDP/TCP 接入或吞吐；最终测试清单与结果以本地运行为准。

未交付：厂商深度解析、中文/子串索引、细分角色、自定义解析器管理、告警、历史回放、导出、历史保留变更、物理清理、备份恢复和跨年后台检索。Web 管理台已接入当前 API，合成预览与真实存储验收分开。全设备 30 天首屏等用户性能要求仍是必须实测的验收条件，不能宣称当前已达标。
