# MCP 服务需求与设计

日期：2026-11-11。状态：**方案已确认，源码已实现；已获准新增三个表、编写迁移并在本机隔离库验证，不部署**。实际验证结果以本机隔离库运行为准。

本方案依据用户本轮明确要求，将 MCP 纳入新增业务范围，取代早期规划中对 MCP 的排除。功能基线以当前 Controller、Service 和前端页面为准，不把规划中的告警、自定义解析器、回放、导出当作已实现能力。架构取舍见 [ADR-0006](../adr/ADR-0006-MCP服务权限与调用审计.md)。

## 1. 目标与页面

新增「系统管理 → MCP 服务」，路由 `/system/mcp`。实施前业务均为一级菜单，本次新增父菜单及其 MCP 子项，不调整既有功能地址。

页面沿用管理台主题、蓝色主色和紧凑白卡，适配暗色与窄屏。两个 Tab 固定命名为「MCP 服务」「调用记录」。只允许登录的有效管理员访问管理页面及其管理 API。

### 1.1 MCP 服务

- 顶部显示运行状态、当前 MCP 接口地址、启用/停止操作、可用工具数量。运行状态区分停止、运行、停止处理中、故障，不能只显示保存的布尔值。
- MCP 默认停止，启停设置持久化；重启读取已保存状态。启动/停止只控制 MCP 入口，不重启 Kestrel、不停止 Syslog 接收、邮件或管理页面。
- 停止立即阻止新调用；已开始操作按其取消及提交边界完成，页面显示进行中的数量。不能撤回已经发送的邮件或已经提交的数据库写入。
- 下方 API Key 表格右上角提供「新建 API Key」。列为名称、Key 标识、只读/读写、权限数、有效期、状态、最近使用、操作。
- 新建抽屉包含名称、授权模式、可空有效期和可搜索的业务权限树。模式默认只读，权限不默认全选；有效期为空表示永久，否则必须晚于当前时间。
- 树采用「业务模块 → 功能动作」，叶子对应后端权限标识。只读模式禁用写叶子，从读写切换到只读时移除写叶子；后台重复校验，不接受伪造提交。
- 名称、模式、权限、有效期创建后不可编辑，不提供更新 API。调整授权必须新建 Key，再吊销旧 Key。
- 行操作为「复制接入指令」「查看授权」「吊销」；已吊销后显示「删除」。到期不等于吊销，到期但未吊销也不能直接删除。
- 吊销立即阻止后续调用，不复用或恢复该 Key；删除不级联删除历史调用记录。已过期和已吊销的 Key 不再生成可用接入指令。
- 业务写入失败保留输入并显示明确错误，例如控制库需要升级、服务停止、权限无效、记录已变更。

### 1.2 调用记录

- 顶部提供自定义留存天数，默认 30 天，允许 1～3650 天，单独保存；显示当前留存设置和最近清理结果。
- 筛选：时间范围、Key、工具/协议方法、连接 IP、结果状态；按时间倒序游标分页。
- 紧凑表格只展示时间、Key 名称、工具/方法、IP、结果、HTTP 状态、耗时、详情入口，不把大段 JSON 塞进表格。
- 详情抽屉显示调用 ID、关联 ID、Key/操作者快照、开始结束时间、耗时、HTTP 与 JSON-RPC 结果、完整请求头、请求参数、原始请求体、响应头、响应体和错误结果。
- JSON 可格式化阅读，并保留原文视图；HTML、邮件正文、原始日志及脚本均作为文本展示，不执行内容。
- 区分尚无 Key、暂无记录、筛选无结果、读取失败、服务关闭和迁移未完成。窄屏表格自身滚动，页面整体不横向溢出。

## 2. 协议与地址

采用官方 C# SDK 的 `ModelContextProtocol.AspNetCore 2.3.1`，在现有单宿主映射 `/mcp`，使用 Streamable HTTP、无会话模式和有限响应，不要求常驻 SSE 通道；响应使用 SDK 对相应协议版本和请求协商后的 JSON 或事件流格式。支持的客户端流程区分协议版本：`2025-11-25` 使用 `initialize`、初始化通知及 `ping`；SDK 当前默认的 `2026-07-28` 使用 `server/discover` 和每次请求的协议版本，不再要求已移除的 `initialize`/`ping`。两个流程均提供 `tools/list` 和 `tools/call`；按实际客户端版本发现或握手，不能将一种流程的成功概括为任意版本兼容。GET 不提供独立事件流时按协议返回 405，不伪装成旧版 HTTP+SSE 服务。依据：[MCP 传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)、[工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)、[官方 C# SDK](https://csharp.sdk.modelcontextprotocol.io/v2/)。

MCP 同时支持已有 HTTP 和 HTTPS 入口，不强制将 `/mcp` 的 HTTP 请求跳转 HTTPS。接口复用现有 Web 监听，不新增宿主端口或自动修改容器端口映射。HTTPS 使用当前管理台证书，包括上传后对新连接生效的证书。正式部署是否暴露 HTTP 仍需对应环境的端口配置。

认证使用 `Authorization: Bearer <API_KEY>`，不接受管理 Cookie 代替 Key，也不接受 URL 参数里的凭据；每次请求重新检查 Key 和服务状态。现有管理页面的 HTTPS、Cookie 和写入保护仍按原入口工作。主机名沿用项目已取消白名单的行为，不新增固定域名/IP 限制；MCP 请求带 Origin 时按传输规范单独校验来源，不把 Origin 与 Host 白名单混为一谈。

本次是 API Key 接入，不新增 OAuth 授权服务器或 OAuth 自动发现；支持客户端显式配置 Bearer 请求头，不宣称兼容仅支持 OAuth 的连接器。该区别依据 [MCP 授权规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)。

复制操作每次直接取 `window.location.origin` 作为 Base URL，再拼接 `/mcp`，保留浏览器当前 HTTP/HTTPS、域名/IPv4/IPv6 和非默认端口。默认端口按浏览器 URL 规范化省略。不能使用服务器内部地址、旧配置域名、当前页面路径、查询参数或 fragment。当前项目按根路径部署，本轮不承诺反向代理子路径前缀支持。

复制文本包含服务名、协议、实际 MCP URL、当前 Key、权限和有效期，以及给智能体的安装说明：识别当前客户端支持的远程 MCP 配置格式，使用指定 URL 和 Bearer 认证，保留已有其他 MCP 配置，仅用协议握手/服务发现与工具列表验证连接，业务写操作须依据后续用户指令调用。不是复制一句缺少地址和认证信息的笼统说明，也不编造跨所有客户端通用的安装命令。

剪贴板受 HTTP 或浏览器策略限制时，显示可全选的指令对话框供手动复制，不能错误提示「已复制」。完整指令不进入 localStorage、URL、前端日志或遥测。

## 3. API Key 与权限

### 3.1 凭据和生命周期

Key 使用密码学随机数生成，随机部分至少 256 bit，带产品前缀和可用于展示的标识；业务 ID 复用集中 `IIdService`，不把业务 ID 当密钥。

**本方案的存储选择：Key 原文和鉴权摘要保存在同一个受控 SQLite Key 记录中，不新增独立密钥目录。** 摘要用于查找与恒时比较；可恢复的原文用于满足「日后仍可从列表复制完整接入指令」。普通列表只返回标识，只有创建成功和管理员主动复制接口返回原文，响应禁止缓存。与仅存哈希、只显示一次的设计相比，这一选择保留了后续复制能力，也意味着读取控制库即可取得有效 Key。数据库及备份应沿用受控数据卷权限；本方案不宣称数据库中的 Key 已加密。

生命周期为有效 → 到期或吊销 → 已吊销后可删除。Key 名称、授权、有效期是不可变快照；最近使用时间和吊销状态为运行信息。删除后历史保留 Key 名称、ID 和操作者快照，避免「未知 Key」丢失追踪。创建人账号停用后，其 Key 即使尚未到期也不能调用。

### 3.2 生效权限

每次调用满足以下交集：服务已开启、Key 存在且有效、创建人仍是启用管理员、访问模式允许该读写类型、已勾选该具体动作。

`tools/list` 只返回允许的工具；直接猜工具名调用仍在 `tools/call` 重新授权。新增工具不会自动授予既有 Key。父节点「全选」仅展开为创建当时的叶子集合，不能存储通配符而意外获得未来功能。

本次为动作权限，不新增设备组/设备范围授权。获得某业务查询动作的 Key 可访问当前系统该业务的数据；当前系统只有管理员角色，不宣称已有多租户或设备级 RBAC。

用户管理、SMTP 修改、证书上传等叶子明确标注管理影响。尤其新建管理员或重置其密码属于账号管理授权，不能将拥有这些动作的 Key 描述为只具有普通运维能力。

MCP 自身启停、Key 签发/吊销/删除、完整调用审计查看和审计留存配置只开放交互式管理员 API，不注册为 MCP 工具。它们是本次接入凭据和审计的管理面，避免 Key 经审计读取其他 Key 或自行扩大授权。

### 4.1 必须保持的业务合同

- 搜索最多 30 天、每页 1～500 条、游标分页、不计算总命中数；关键词目前是区分大小写的 ASCII 全词 AND，不偷偷升级为中文模糊搜索或任意 SQL。
- 报表复用现有 `GetReportAsync`，最多 31 天；是所选范围合计最近 10 条高严重级别日志。需要「每设备 10 条」时分别查询对应设备，不能把合计结果标成每设备结果。
- 首页速率历史目前由浏览器对累计量差分生成。MCP 返回真实累计值及采样时间，不伪造后端历史速率序列。设备计数与系统队列/数据库/故障指标分别置于 source/system，不能把系统待写入量归属到选中的设备。
- 未登记样本是内存数据，重启清空；来源登记后不再出现在未登记列表。
- 清空只覆盖已有业务定义范围，不承诺删除尚未入库的队列；并发清空、ClickHouse 超时与未知结果沿用 `LogClearService`。
- 邮件 accepted 仅代表 SMTP 接收，不代表收件箱投递；本轮不扩展任意内容发信、历史邮件重发或立即发送指定周期报表。
- 来源、用户、报表订阅当前没有删除业务，工具提供启停，不凭空新增删除。自定义解析器、告警规则、回放、导出和备份不注册空工具。

## 5. 业务复用与授权改造

实施前多数写服务接收 `actorId + Cookie token`，并在 SQLite 事务内调用 `IsCurrentAdminAsync`。本次引入统一操作主体，明确区分管理员会话和 MCP Key，包含操作者 ID、Key ID、请求关联号、具体动作。只能由已认证入口构造；不能接受工具参数传入操作者或权限。

在原业务提交事务内重新核对账号和对应凭据状态，保留原可靠操作审计。不能伪造 Cookie、给 MCP 偷建管理会话或写绕过权限的第二套业务实现。创建/修改来源等现有校验不一致处一并收敛。

窄动作采用窄 DTO，并在持锁事务中读取和合并目标字段；已存在版本的业务保留版本冲突检查。创建动作允许设置新对象初始配置，但创建不变成覆盖既有对象的入口。全量来源更新、监听保存、用户更新及订阅更新不能绕过独立启停/保留/忽略权限；没有对应叶子即拒绝相关变更。

## 6. 全量审计与留存

**按用户本轮要求，MCP 专用调用记录原样保存应用可见的请求/响应，不做字段脱敏。** 这包括传入的 Authorization、Cookie，以及工具参数中实际提交的密码、邮件授权码、证书内容等；因此查看完整调用记录的管理员能看到其中的凭据。现有业务响应没有返回的秘密不另行读取补入审计。该规则只适用于 MCP 专用审计，不将这些内容复制到普通应用日志、异常响应、公开文档或测试报告。

记录范围包括对应协议版本的服务发现/初始化、通知、ping、工具列表和调用，以及进入应用入口后的鉴权失败、权限拒绝、参数错误、服务停止、成功、业务失败、取消及结果未知。实际 IP 为连接对端；转发头原样保存，只有配置可信代理后才另列推导的客户端 IP，不把任意 `X-Forwarded-For` 当事实。

完整性针对应用实际看到的 HTTP 请求和生成的响应，不是 TLS/网络抓包。非法 TLS 握手、由反向代理/Kestrel 提前拒绝的请求无法保证有应用审计。多值头用数组保留；请求/响应保留原始 UTF-8 字节内容及可解析 JSON。响应状态、HTTP 方法、原始 URL/查询串、关联 ID 和字节数一并保存。

MCP 请求正文上限 1 MiB、实际序列化协议响应上限 4 MiB，满足 256 KiB 证书的 Base64 包装；仅对 `/mcp` 配置，不全局扩大现有 API 上传限制。响应预算按实际 UTF-8 字节计算，包含 SDK 同时返回的文本内容和结构化内容，不能只计算一份业务结果。管理台详情接口对这两份完整原文进行 JSON 包装时还可能产生转义膨胀，因此前端仅对 MCP 审计详情允许 32 MiB 响应读取预算，其余接口保留 20 MiB 限制。合法预算内内容完整保存，不能静默截断再显示「完整」。超限拒绝、客户端中断和传输捕获不足要标明原始长度/已捕获长度与未完整原因；大查询要求缩小页，不返回伪造完整数据。捕获阶段独立最多 32 个租约；超过该数量时不读取正文，只审计元信息并标记捕获不完整，以 429 拒绝。业务执行全局最多 16 个并发、每 Key 最多 4 个；连接 IP 每分钟 240 次、Key 每分钟 120 次，查询继续复用既有预算。

调用进入执行阶段前先可靠保存请求和 `started` 状态；保存失败返回 `mcp_audit_unavailable`，不执行工具。SQLite 业务变更与原有操作审计继续同事务。完成时保存实际结果，再返回响应。

外部动作不能与本地 SQLite 构成一个事务。例如 ClickHouse 清空已执行，而补写结果失败时，只能保留调用 ID、说明结果未确认；不能简单回复失败诱导客户端再次清空。网络断开也不等于取消成功，破坏性/外部动作不得自动重试。重启后发现未完成记录标为中断/结果未知，不自动重放工具。恢复失败时 MCP 状态为故障并阻止新调用，管理台显示恢复错误且允许重试启动；不因此停止管理台或其他业务。

留存 worker 使用短事务分批清理超过天数的已完成 MCP 记录；保留进行中的记录并恢复标识中断记录。只影响 MCP 调用表，不清理 Syslog 日志、邮件历史或原有管理员操作审计。缩短天数时页面提示其会删除较早的调用记录。清理失败显示错误与最近成功时间，不假报空间已回收；SQLite 删除记录不等于数据库文件立即缩小，不自动执行全库 VACUUM。

列表显式只查摘要列，详情按 ID 加载正文，不在 JSON 大字段上做无界模糊搜索。删除 Key 不影响审计；保留 Key/用户名快照以支持删除后的查询。
