# ADR-0002 管理员配置与显式网页初始化

- 状态为接受。
- 日期为 2026-11-10。
- 用户已确认按[用户管理与首次启动实施方案](../spec/用户管理与首次启动实施方案.md)实施。

## 背景

用户要求后台配置账号，并在系统首次启动时进入管理员配置页。现有控制库已经具有账号、启用状态和会话版本，但管理员初始化仅有命令行入口。普通启动不得自行创建数据库或默认账号。

## 决定

新增显式网页初始化入口。访问和状态探测只读，只有用户提交首次管理员配置时才允许执行既有版本 1 控制库 SQL，创建账号及可靠审计。已存在完整空账号库可直接创建首个管理员，数据库异常、结构残缺或版本不支持时停止，不自动补表或迁移。

首次创建需 HTTPS、同源写请求保护、限速和服务器本机直连。客户端转发头不能作为本机身份依据，初始化入口不得经反向代理开放。成功后进入登录，任意账号已存在时关闭匿名初始化，不能因为账号停用重新开放。命令行维护入口保留。

用户管理沿用现有 `admin` 角色和控制表。新建、改名、启停及重置密码由服务端校验，变更、会话撤销及审计同事务。复用 `session_version` 做乐观并发检查，停用和改密会使旧会话失效。保留最后一个启用管理员，禁止本人停用及通过管理入口重置本人密码。

## 理由与影响

这样可以提供完整首次使用引导，同时保持启动无隐式写库、不设默认密码、不改写历史 SQL的边界。多管理员管理不需要新增存储依赖或扩展表结构。本次没有引入只读角色和设备组权限，页面明确标示管理员拥有现有全部管理权限。

本决定增加了命令行以外的显式初始化入口，修订相关运行说明，但不改变 ADR-0001 的 ClickHouse/SQLite 职责。实际部署的 HTTPS、网络入口及数据库操作仍按环境授权。数据库故障不能作为重建或重新注册管理员的依据。

## 验证

使用隔离 SQLite 和进程内 HTTP 测试验证初始化一次性、并发冲突、故障拒绝、事务审计、账号保护和会话失效。真实浏览器使用合成数据验证首次引导、管理页面及六语帮助。实际检查结果以本地运行为准。
