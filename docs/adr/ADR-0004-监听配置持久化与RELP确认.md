# ADR-0004 监听配置持久化与 RELP 确认

- 状态：接受。
- 日期：2026-11-10。
- 依据：用户明确同意新增接收配置菜单、四种协议、监听配置表以及保存后重启生效。
- 相关：[接收配置与 RELP](../spec/接收配置与RELP.md)。

## 背景

原实现的 UDP / TCP / TLS 监听来自部署配置，没有网页配置入口和逐端点状态；RELP 尚未实现。既有 SQLite 不含通用配置表。配置保存需要可靠审计与重启后恢复，运行中的端口不应随编辑即时变化。

## 决定

新增单例 `listener_settings` 表，版本化 JSON 只包含接收开关、四种协议的绑定、端口、帧设置、超时和证书标识。配置与审计同 SQLite 事务保存，乐观版本冲突返回 409。使用新的显式迁移 `002`，不重写历史 `001`；普通启动不迁移。新初始化执行两份 SQL，已有版本 1 通过 `--migrate-listeners` 升级。

宿主启动前一次性读取已保存配置，保存操作只产生待重启配置。已保存版本覆盖部署的监听字段，`Ingest:ForceDisabled` 保持最高优先级关闭能力。TLS 密码与文件路径只来自服务器受控配置，网页和 SQLite 只引用证书标识。端点绑定及证书错误独立暴露，单端点失败不取消其他端点。

新增明文 TCP 的 RELP v1。对已登记启用来源，在现有文件暂存追加成功后确认；对未登记来源延续 [ADR-0003](ADR-0003-未登记设备有界内存暂存.md) 的有界内存样本语义，ACK 只代表暂存到样本缓存。不会把内存观察样本改成持久化正式日志。

## 理由与影响

复用 SQLite 事务使配置变更和可靠审计保持一致，避免配置文件与审计分别写入导致的崩溃窗口。重启生效保持运行快照确定性，并让管理员区分保存、应用和成功监听三个结果。代价是一次显式结构迁移，以及变更端口时的服务重启。

RELP 成功 ACK 不等于 ClickHouse 写入成功。未收到 ACK 的发送端可能重试已暂存消息，当前不提供跨连接去重或 exactly-once。RELP over TLS、真实发送端互操作、真实证书信任链、掉电恢复与吞吐仍需后续授权及验证。本决定不改变设备端口、证书部署、生产发布和删除操作的既有权限边界。

## 验证

覆盖配置校验、审计回滚、并发版本、旧库迁移、普通启动只读、重启前后快照、管理员鉴权、RELP 帧及确认语义。实际构建、测试和浏览器结果以变更记录为准，不从源码或模拟流测试推导真实网络验收。

## 运行期开关补充

用户要求保存后通过关闭再开启日志接收总开关应用配置。保存仍只写入配置与审计。运行期开关复用版本 2 表和管理员事务审计。关闭时停止接收端点和现有连接，开启时读取最新保存端点并重建监听器。队列、文件暂存、写入任务及未登记样本留在宿主内，切换期间管理台保持可用。宿主启动也可应用持久保存的配置。详细行为见[接收配置与 RELP](../spec/接收配置与RELP.md)。
