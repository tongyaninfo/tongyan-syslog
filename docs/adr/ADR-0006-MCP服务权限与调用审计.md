# ADR-0006 MCP 服务、权限与调用审计

- 状态：已接受，用户于 2026-11-11 确认实施和本机隔离验证，不部署。
- 日期：2026-11-11。
- 相关：[MCP 服务需求与设计](../spec/MCP服务需求与设计.md)。

## 背景

用户要求在系统管理增加 MCP 服务，具备独立启停、不可编辑的 API Key、只读/读写及动作权限、当前浏览器地址生成的接入指令、完整调用记录和可配置留存，并支持 HTTP/HTTPS。实施前系统没有 MCP、细粒度 Key 权限或调用审计表；写服务普遍在业务事务内验证管理员 Cookie 会话。

## 决定

1. 在现有 ASP.NET Core 单宿主以官方 C# SDK 承载 Streamable HTTP `/mcp`，独立 Bearer 认证和启停，不新增进程、接收端口或消息组件。
2. 用统一操作主体承接管理会话与 MCP Key，保留业务事务内鉴权；权限目录同时驱动工具发现、执行和前端权限树，复用现有服务能力。
3. SQLite 控制库新增三个表，通过版本 5 显式迁移建立；普通启动不自动迁移，ClickHouse 表结构不变。
4. 为支持从列表再次复制完整接入指令，Key 原文和摘要保存在同一受控 SQLite 记录；不引入额外密钥目录。列表不回显原文，复制接口限交互式管理员使用。
5. 按本轮明确要求，MCP 专用审计保留应用可见的完整请求和响应，包含请求中实际出现的凭据；不复用普通脱敏日志，也不把专用审计开放给 MCP Key。记录大小、进行中状态、外部副作用和捕获不足边界必须可见。
6. HTTP/HTTPS 支持限定于 MCP 入口，不顺带放宽既有管理 Cookie 接口。复制地址每次取浏览器 origin；本轮不实现 OAuth 或反向代理子路径部署。

实施锁定 `ModelContextProtocol.AspNetCore 2.3.1`，提供 39 个业务工具。`2025-11-25` 采用初始化与 ping，SDK 默认的 `2026-07-28` 采用服务发现及每请求协议版本，不混用两版握手流程。接入指令保持按客户端支持的协议发现或握手，再读取工具列表。

完整审计的请求预算为 1 MiB，实际序列化响应预算为 4 MiB；后者同时包含 SDK 的文本与结构化内容，以最终协议字节计量。超限或捕获不足显式记录，不以静默截断替代完整记录。调用恢复失败只阻止 MCP 接入，保留管理员重试入口。

## 理由与取舍

单宿主复用现有业务和部署方式，但继续共享进程故障域，需有界并发及查询预算。仅存不可逆摘要不能满足后续无须找回原 Key 的完整指令复制；明文可恢复存储和全量请求审计意味着控制库、其备份及调用记录访问者都可能取得凭据，这一点必须准确呈现。

调用审计与原业务审计职责不同。外部操作完成和补写审计不是一个跨系统事务，不能承诺永远完整或发生断线即可安全重试；实施要保留意图、结果未知与调用关联号。

当前已有业务工具与未实现功能的界线、页面、表结构、管理 API 和隔离验收均由关联方案维护，不在本 ADR 重复清单。

## 授权与后续

用户本轮已明确允许新增三个 MCP 表、编写 v4→v5 迁移并在本机隔离库验证，同时明确不要部署。该授权已满足本方案实施的结构变更前置条件。真实控制库迁移、设备接收端口、真实发信及服务器部署仍需对应授权；实际验证结果以本机隔离库运行为准。
