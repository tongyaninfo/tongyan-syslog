# ADR-0005 邮件通知与周期报表

- 状态：接受
- 日期：2026-11-11

## 决定

- 管理员在「通知设置」维护一套 SMTP 配置、多个周期报表订阅及发送记录。测试邮件使用已保存的配置。主题前缀可编辑或留空，应用于新排队的所有邮件。TLS 默认启用，支持直连 TLS 和强制 STARTTLS。明文模式仅用于无认证中继。
- SQLite 版本 4 增加 SMTP 配置、报表订阅和发送记录三张表。配置、订阅与测试请求的审计在控制库事务内提交。发送记录也作为持久化队列，后台单并发发送。SMTP 事务在 SQLite 写事务之外执行。
- SMTP 授权码与邮件配置一起明文保存到 SQLite 控制库，数据库文件及备份仅供受信账号访问。API、错误及审计不返回授权码。修改 SMTP 连接或登录设置时，启用认证需要重新填写授权码。
- 调度按上海时间计算上一个完整自然日、周或月。以订阅、周期开始和收件人去重。停机跨越多个周期时最多补发最近一个。对明确的临时失败最多尝试三次。中断后无法确认的任务标记为「结果未知」，不自动重发。SMTP 接收成功不表示收件人已读或已送达收件箱。
- ClickHouse 报表查询按来源和接收时间读取截至生成时仍可检索的日志，按设备统计并展示严重级别 0–3 合计最近 10 条。系统运行数据是生成时快照。模板在 `Syslog.Api/Resources/Email/` 作为嵌入资源随程序发布，邮件包含 HTML 和纯文本正文。发送记录保存有大小上限的正文快照，不依赖原始日志是否仍在 ClickHouse。

## 升级

新库通过现有显式初始化路径建到版本 4。既有版本 3 控制库停止宿主、备份后执行 `--migrate-notifications`，再启动新版。版本 1、2 先按顺序执行原监听和来源过滤迁移。普通启动不会迁移。报表查询不需要改 ClickHouse 表结构。

```sh
dotnet Syslog.Api.dll --migrate-notifications --ControlStore:ConnectionString "Data Source=/path/to/syslog-control.sqlite;Mode=ReadWrite"
```

先用隔离 SMTP 中继验证发送和错误处理，再在通知页配置实际 SMTP 并发送测试邮件。既有邮件历史与 ClickHouse 日志清空独立管理。

授权码直接存储沿用现有表和列，无需迁移。已加密的授权码仍使用原密钥目录读取，重新填写并保存后改为直接存储。原密钥不可用时可重新填写授权码。若回退至只支持加密存储的旧版，须在旧版中重新填写授权码。
