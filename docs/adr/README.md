# 架构决定记录（ADR）

本目录记录重要的架构决定与替代关系，避免同一问题反复讨论或实现漂移。当前已接受 ADR-0001 的单宿主与双存储职责方向；真实环境和性能仍待验证。以下为维护规则、模板与后续议题。

## 何时需要 ADR

- 影响多个模块或长期维护的决定：技术选型、进程/部署边界、协议帧界定、存储选型、授权模型。
- 存在明显取舍且以后可能被重新提出的决定。
- 会改变公开合同、升级路径或安全边界的决定。

小范围实现细节不需要 ADR，写入变更记录即可。

## 命名与状态

- 文件名：`ADR-0001-标题.md`，编号递增，不复用。
- 状态：`提议` → `接受` / `拒绝`；被后续决定替代时标记 `已被 ADR-XXXX 替代`，不删除原文。
- 修订通过新增 ADR 或追加「修订」小节完成，不改写已接受决定的历史理由。

## 模板

```markdown
# ADR-0001 标题

- 状态：提议 / 接受 / 拒绝 / 已被替代
- 日期：YYYY-MM-DD
- 相关：方案、接口、变更记录链接

## 背景
要解决的问题、约束与已知事实。

## 决定
选择什么，边界在哪里。

## 理由
为什么这样选，与其他方案的关键差异。

## 影响
对目录、接口、数据、部署、安全与验证的影响。

## 后续
需要补充的验证、待确认项与可能的替代触发条件。
```
