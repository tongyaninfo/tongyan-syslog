## 源码职责

### 后端

- Syslog.Shared：ApiResult、LogEvent、LogSource、LogSearch、解析/发号/来源/日志存储接口；不放宿主和存储实现。
- Syslog.Engine：RFC 5424/3164 基础解析与纯帧解码，不依赖网络、数据库或 ASP.NET Core；告警、自定义解析器和回放仍待实现。
- Syslog.Ingest：由 Api 引用的接收模块，含 UDP/TCP/TLS/RELP 工作器、有界队列、文件暂存与 ClickHouse HTTP 访问；监听默认关闭。
- Syslog.Api：单一组合宿主，负责 SQLite 控制库、管理员会话、来源与保留天数、监听配置、审计、日志检索/详情和状态入口；生产形态承载前端构建的静态资源，管理 API 保持同源 HTTPS。
- 依赖方向：Api → Ingest / Engine / Shared；Ingest → Engine / Shared；Engine → Shared。Ingest 不反向依赖 Api。
- 管理服务负责 SQLite 写入，日志存储适配器负责 ClickHouse 写入；普通启动不自动创建或迁移任何数据库。

项目内部按 Models、Service、Service/impl、Common、Options、Middleware、Workers、Data 分类。SQL 与持久化合同在 Data，合成测试在 tests；不将口令或真实日志写入代码和测试。

### 前端

已建立 React 19 + Umi Max + Ant Design 6，沿用 Ant Design Pro 6.0.3 最小模板基线。路由、页面、services、access 和 locales 按模板约定；登录、总览、日志检索与详情、来源和保留设置接入现有 API 合同。样式沿用通研统一管理台风格，保留蓝色主色、浅底白卡与紧凑布局，不引入 AI、地图、外网字体或 Git hooks。

原文按纯文本和字节证据预览，检索遵循最长 30 天与游标合同，没有命中总数。合成预览默认绑定 `127.0.0.1:8019`，明确获准后可监听 `0.0.0.0:8019` 供局域网查看；具体命令、制品复制与旧哈希文件回收边界见[前端说明](../frontend/README.md)。

「接收配置」采用独立路由、API 和 SQLite 单例配置。重新开启日志接收总开关可应用已保存的端点设置，四种协议与确认边界见[接收配置与 RELP](spec/接收配置与RELP.md)。

### 规则、文档与交付

规则数据统一放 [rules/](../rules/README.md)，解析实现放 Engine。自定义规则版本流程与告警尚待实现，不把规则目录存在当能力完成。

文档按 spec/api/adr/releases 分层；README 负责导航。deploy 目前没有获准交付环境或部署验收，scripts 没有的命令不能虚构。入口见[文档中心](README.md)。

## 一期边界

一期目标仍包括标准接收、解析器版本、结构化检索、原文、长期保留、告警、多用户审计、HTTPS 管理台和跨产品来源。当前仅首批后端及对应管理台实现：仅管理员角色、ASCII 全词 AND 关键词查询、单请求最长 30 天、来源级新事件保留设置。中文/子串、历史查询任务、告警、回放、导出、历史保留变更、物理清理和备份仍未完成；前端没有为这些能力添加占位导航。

不包含主动封禁或阻断、多租户 SaaS、跨集群分布式存储、完整 SIEM、内置 AI 分析与桌面客户端。MCP 按 2026-11-11 用户确认纳入扩展范围，已实现 39 个工具与管理页面，见 [MCP 服务需求与设计](spec/MCP服务需求与设计.md)；新增三表及迁移仅获准在本机隔离验证，不部署。完整范围见[功能需求清单](spec/功能需求清单.md)，首批已实现合同以[首批存储实施合同](spec/首批存储实施合同.md)为准。

## 架构待定项

单宿主及 ClickHouse/SQLite 职责已决定。以下仍需实测或独立决定，不能从本次单元测试推导：

- ClickHouse 锁定版本上的 SQL、text 索引、排序/投影、压缩收益及全设备查询延迟。
- 实际交换机/ESXi 的 TCP/TLS 帧、消息长度、信任链与发送端丢失边界。
- 发送结果未知的对账工具、文件暂存掉电与目录项持久性、确认残留回收。
- 中文/子串检索分词、历史检索任务、解析器版本化与回放修订。
- 保留历史变更、物理删除屏障、备份恢复与容量治理。
- 告警窗口、通知幂等、设备组/细分角色及对应管理页面。
- 独立实例汇聚时的 ID 命名空间；首版发号仅覆盖同一控制库。

## 与其他产品的关系

沿用 src/tests 分离、中文工程注释、统一 ApiResult、集中业务发号、UTC 与字符串 ID。跨产品接入只接收和查询，不反向执行其他产品的策略，不沿用其他项目的服务器或历史授权。
