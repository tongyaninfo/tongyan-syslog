# systemd 服务单元

本目录为占位目录，当前**没有服务单元文件**。后端工程已建立，采用单 Api 宿主组合接收模块；后续在获准目标环境建立并验证 Linux 服务单元。

## 规划

| 单元 | 职责 |
| --- | --- |
| `tongyan-syslog.service` | 单宿主：HTTPS 管理 API、来源与控制库、接收解析和 ClickHouse 批量写入 |
| ClickHouse 官方服务 | 独立的日志存储服务，版本、账号与资源限制由具体环境确定 |

## 约定

- 以专用非 root 账号运行；接收低端口（< 1024）需单独确认能力，或改用高位端口并在网络侧重定向。
- 数据目录、归档与备份使用宿主目录并显式配置；工作目录与数据目录分离。
- TLS 接收证书与管理证书通过受控路径或环境变量提供，不写入单元文件明文。
- 启动前显式初始化控制库和 ClickHouse，再启动单 Syslog 宿主；接收默认关闭。停机先确认设备转发与暂存状态，内存中尚未持久的数据可能丢失；不得把停止服务视为已完整排空。
- 服务单元不包含自动建库、自动迁移或自动删除数据的命令；维护动作由显式入口执行。
- 失败重启有上限与退避；不无限重启，不因重启掩盖证书或数据库错误。
- 实际端口、账号、路径与单元是否生效须在目标环境验证并记录，不能以单元文件存在作为已部署依据。

入口见[部署说明](../README.md)与[项目目录规划](../../docs/项目目录规划.md)。
