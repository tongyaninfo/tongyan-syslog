# 部署

本目录提供 [docker/](docker/README.md) 容器部署资产（Dockerfile、Compose 与服务配置模板）。`systemd/` 与 `config/` 为占位目录，尚未建立服务单元与配置示例。

通研 Syslog 处于 0.1.0 首批实现阶段，已建立单 Api 宿主、接收/解析/暂存模块、ClickHouse HTTP 适配与 SQLite 控制存储；Web 管理台已有首批页面。真实设备、长期运行、吞吐与真库性能尚未验收。

本仓库不包含任何真实交付环境的主机、地址、账号、口令或证书。部署、开放端口、防火墙操作、服务重启和数据卷变更必须针对具体环境取得授权。

## 单实例部署形态

| 组件 | 规划 |
| --- | --- |
| .NET 应用 | 单个 Syslog.Api 宿主组合 Ingest / Engine / Shared；管理 API 和接收工作器共享进程故障域 |
| Syslog 接收 | Ingest 默认关闭且监听器列表为空；UDP 514、TCP 514、TLS 6514 是规划端口，实际由环境配置并授权 |
| 管理入口 | 默认受控 HTTPS 地址；证书和访问边界需环境验证 |
| 日志存储 | 独立单节点 ClickHouse；SQL 与 text 索引尚未真库验证 |
| 管理存储 | 同宿主内嵌 SQLite WAL，保存账号、来源、保留设置、发号与可靠审计；不额外运行数据库服务 |
| 进程管理 | Linux systemd；容器形态作为另一种部署选项 |
| 前端 | 构建后由 Api 同源托管 |
| 证书 | TLS 接收与管理 HTTPS 使用各自证书，挂载或受控配置提供，不写入镜像 |

## 网络与端口边界

- 接收端口是宿主网络入口：放行、绑定地址与来源范围按环境单独确认，默认不对公网开放。
- 管理端口与被接收流量分开暴露；管理入口应通过内网、VPN 或来源白名单限制。
- 容器网络形态（host 或映射端口）会影响 UDP 与来源地址识别：NAT 后可能丢失真实来源，必须在目标环境验证。
- 系统不自动替用户修改防火墙；不提供「一键放行」或静默改规则的行为。
- 端口冲突、绑定失败、权限不足或 TLS 证书无效时不能把监听报告为已生效。

## 初始化与升级

首次部署需审阅并在获准环境显式初始化 SQLite 和 ClickHouse，普通启动不自动建库、不迁移。SQLite 已有显式初始化与管理员引导入口，ClickHouse 提供人工审阅 SQL；具体配置和步骤见[首批后端运行与验证](../docs/spec/首批后端运行与验证.md)。这些入口不代表已完成可升级版本链，通用升级、备份与恢复工具尚未实现。

后续升级前需停止应用接收与管理写入、核对 ClickHouse 在途请求、确认备份与恢复方案；各存储分别核验兼容性。维护失败保留原库、备份和待核对状态，不覆盖或自动降级。

保留期、容量与删除属于运维动作，须在方案确认后按环境执行并记录。当前按 `expires_at` 隐藏到期日志，但没有物理清理任务或 DELETE TTL；配置保留期不等于磁盘空间已回收，不能将首批代码作为已完成长期生产留存治理的系统。
