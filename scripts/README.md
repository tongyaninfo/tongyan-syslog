# 开发与验证脚本

本目录存放仓库级检查脚本。已实现 `check-docs.mjs`，使用 Node.js 内置模块检查本地 Markdown 链接；不校验锚点或外部 URL，不读取部署环境信息、运行数据或 Git 状态。

```sh
node scripts/check-docs.mjs
dotnet build backend/Syslog.slnx
dotnet test backend/Syslog.slnx --no-build
```

链接检查失败返回退出码 1。测试使用合成数据；内存 SQLite 已获本次授权，文件暂存测试保留忽略目录中的合成产物，不删除文件。上述检查不会启动真实接收端口或初始化 ClickHouse。

## 规划脚本

| 脚本 | 预期职责 |
| --- | --- |
| `check-docs.mjs`（已实现） | 检查仓库 Markdown 的本地相对链接，跳过依赖、构建产物与运行时数据 |
| `verify.mjs` | 按文档、后端、前端三个范围调度检查；未建立工程时明确报告未运行 |

## 约束

- 脚本使用 Node.js 内置模块，不依赖第三方包，无需安装依赖即可运行。
- 默认只读检查；涉及删除、格式化、联网、数据库或 Git 的动作必须显式传参并取得授权。
- 结果区分通过、失败、跳过与未运行；被环境阻断时不得把未执行报告为通过。
- 脚本建立后在此补充真实用法、参数、退出码和覆盖范围，并同步根 [AGENTS.md](../AGENTS.md) 的验证要求；在此之前不提供不可执行的入口。
- 不把个人绝对路径、宿主账号或真实日志样本写入脚本与示例。
