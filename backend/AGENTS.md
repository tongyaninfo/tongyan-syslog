# 后端开发规则

本文件补充根 [AGENTS.md](../AGENTS.md)，适用于 `backend/`。根规则始终优先；当前工程状态与规划结构见 [README](README.md)。

## 工程结构

- 四个项目保持单向依赖：`Syslog.Api` → `Syslog.Ingest`、`Syslog.Engine`、`Syslog.Shared`；`Syslog.Ingest` → `Syslog.Engine`、`Syslog.Shared`；`Syslog.Engine` → `Syslog.Shared`。`Syslog.Api` 是单一宿主，`Syslog.Ingest` 是由宿主组合的接收与日志存储模块。
- `Syslog.Engine` 不得引用 ASP.NET Core、宿主类型、系统命令或环境配置，保持可离线单元测试与回放。
- `Syslog.Ingest` 是接收数据面模块：监听 UDP / TCP / TLS / RELP、按来源限速、调用解析、暂存与批量写入；日志存储服务拥有 ClickHouse 日志写入权，接收默认关闭。
- `Syslog.Api` 是管理 API 与组合宿主：负责认证、来源、检索入口、运行状态及 SQLite 控制库写入。管理变更与审计同事务；导出、备份和前端托管按后续实现交付，不能把职责规划写成已实现。
- `Syslog.Ingest` 不反向引用 `Syslog.Api`；共享合同放 `Syslog.Shared`，模块通过依赖注入组合。单宿主共享故障域，不能承诺进程级隔离；架构决定见 [ADR-0001](../docs/adr/ADR-0001-轻量化长周期日志架构.md)。
- 依赖版本集中管理；初始化后将解决方案、项目文件与锁定文件纳入版本控制，不按模块各自锁定不同版本。

## 接收

- 监听器按协议与来源显式配置：UDP 有报文大小上限，TCP / TLS 有单连接读取上限、空闲超时与最大并发；任何缓冲都有上界。
- 来源识别与限速放在接收入口：按来源地址与监听器统计速率，超限报文记录并丢弃，不能拖垮进程；不把来源地址直接当作可信身份。
- 接收阶段只做「校验、计数、入队」：不在网络回调里同步解析或写库；队列满时按配置的策略丢弃并增加丢弃指标。
- UDP 允许有界丢失，TCP / TLS 允许背压与断开；两者都必须暴露接收、丢弃、字节与错误计数。不得把接收到表述为已入库。
- TLS 证书、私钥与监听地址来自受控配置或部署挂载，不写入代码、镜像或日志；证书无效时拒绝启动对应监听器并报告，不回退明文。
- 接收端不得成为命令执行入口：报文内容只作为数据处理，禁止拼接命令、SQL 或文件路径。
- 接收与解析不得依赖管理 HTTP 请求；普通查询失败不应阻塞接收，但单宿主退出会同时停止两者，状态通过指标与只读接口体现。

## 解析与规则

- 解析保持纯函数式、确定性：输入为原始报文、解析器版本与来源信息，输出为结构化事件、字段置信度、解析状态与失败原因。
- 协议解析先覆盖 RFC 5424 与 RFC 3164，明确各自的时间格式、结构化数据、PRI 与编码处理；无时区与非法时间必须给出确定解释并保留原始值，不静默猜测。
- 解析器链按来源与格式选择，顺序固定且可配置；同一报文只应用一个主解析器，补充解析不得覆盖原始字段而不留痕。
- 解析失败默认保留原文、失败原因与来源，供修正后回放；回放必须幂等，不重复累计。禁止以「重试」为名无限放大队列。
- 解析器与告警规则来自 `rules/`，加载时校验格式、版本与摘要；非法或不兼容的规则拒绝启用并保留上一版本，不默认放行。
- 规则求值不得读库、写文件或执行命令；告警阈值、窗口、静默期与冷却期由服务层按快照计算，重复触发不能无限通知。
- 每条解析结果记录使用的解析器标识与版本，便于回溯「为什么这条日志被这样理解」。

## 存储与留存

- 日志采用单节点非复制 ClickHouse，管理数据采用本机 SQLite WAL。ClickHouse 首次访问时使用仓库审核过的 SQL 创建配置所需的缺失库表，校验既有结构。SQLite 普通启动不建库，既有库表与索引的迁移均需显式管理。
- 写入走有界队列与批量提交；队列满、存储故障或进程退出可能产生缺口，必须暴露写入失败、积压、丢弃与最后成功时间。
- 原始报文与结构化字段分别存储或分别标记：原文受大小上限保护，结构化字段可重建但不得覆盖原文证据。
- 保留期与容量治理必须可执行、可观测：删除与归档有范围、审计与完成状态，失败要报告而不是静默跳过。
- 管理员审计与业务日志使用不同写入路径；审计失败时不得返回操作成功。
- 后台任务（解析回放、保留清理、告警扫描、备份）必须可取消、可观测、可重入，不无限重试，不与接收写入争抢唯一写者。
- 迁移只由显式维护入口在停写状态下执行；后续拆分宿主时也不得并发迁移同一存储。首次配置页面的明确提交可在本机 HTTPS 限制下初始化不存在的控制库，依次使用版本 1 与监听配置版本 2 SQL；既有版本 1 使用显式迁移命令升级。状态查询和普通启动不得建库或迁移，损坏或未知版本不得自动修复。

## 接口与安全

- 业务接口统一使用 `ApiResult<T>` 与真实 HTTP 状态码；分页、排序、时间范围与错误码在合同文档中固定。
- 管理接口默认需要认证；危险操作（删除来源、删除日志、变更保留期、导入规则、导出）要求更高权限并记录审计。
- 检索接口必须有时间范围、结果条数与字段大小上限，禁止无界全表扫描；导出异步进行并受权限与留存约束。
- 原始报文返回时按文本处理，接口不承诺将其作为 HTML 或富文本渲染；响应头与前端渲染共同避免内容注入。
- 错误响应不包含连接串、内部地址、堆栈、解析器内部路径或宿主命令。
- 上传、导入与规则解析限制大小、类型与解析时长；不执行导入内容中的任意命令。

## 验证

- 初始化完成后必须能运行：`dotnet build`、`dotnet test`。
- 解析测试覆盖 RFC 5424 / 3164、结构化数据、无时区、非法 PRI、超长报文、截断与编码边界；样本使用合成报文。
- 接收测试覆盖 UDP 报文上限与丢弃、TCP 半包/粘包、TLS 证书失败、来源限速、队列溢出与并发上限。
- 检索与保留测试覆盖时间范围、字段过滤、分页上限、删除范围与审计；数据库与迁移验证只使用获准的隔离实例。
- 告警测试覆盖阈值、窗口、静默、冷却与通知失败状态；不得把「规则命中」当作「通知已送达」。
